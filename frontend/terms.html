Privacy policy

Effective 12 November 2026

SmileBERTa collects as little as it can get away with. There are no analytics scripts, no advertising, no tracking cookies and no third-party trackers of any kind on this site. Nothing about you is sold or shared for marketing, because none of it is collected in the first place.

What is stored

Account
The username you register with — usually an email address — and your password, stored only as a salted PBKDF2 hash. The plain password is never stored and cannot be recovered, only reset.
Saved work
Anything you explicitly save to your Workspace: molecules, fragments, classifications, linked leads, docking runs, structures and ADMET profiles, with the name you gave them.
Fragment library
Fragments you choose to save, with their depiction and computed properties.
Session token
A random token identifying your signed-in session, valid for 90 days. It is kept in your browser's local storage, not in a cookie.
Client identifier
A random string your browser generates and keeps in local storage, sent with requests so that docking rate limits apply per person rather than per network — otherwise everyone sharing a university connection would share one quota. It identifies a browser, not a person, contains no personal data, is never linked to your account, and clearing your browser storage resets it.

That is the complete list. No name, institution, phone number, location or payment information is requested or stored.

What is not stored

  • Your IP address is not logged to the database. It is held briefly in server memory to enforce docking rate limits, and is discarded. It is never written to a record you or anyone else can read back, and the job-status API deliberately omits it.
  • Molecules you work on but do not save. If you profile, dock or classify something without saving it, it is processed and discarded.
  • No browsing history, device fingerprint, or behavioural profile.

Ordinary web-server request logs kept by the hosting providers below may include IP addresses, as they do for any website.

Where your data goes

Running the service necessarily involves these third parties. Each sees only what is described:

Render
Hosts the website and the main API. Sees all requests to them.
Neon
Managed PostgreSQL. Stores the account and saved-work data listed above.
Hetzner
Hosts the docking service. Receives the protein structure and ligand of any docking job you run. Jobs live in memory and are not written to a database.
RCSB PDB
Protein structures are downloaded from RCSB by the server when you load a PDB ID, so RCSB sees the request.
Hugging Face
The Model Hub queries the public Hugging Face model API with your search terms. Notebooks you generate download models directly from Hugging Face when you run them.
SMILES corrector
When a predicted fragment is not a valid structure, the predicted SMILES string is sent to a separate correction service to be repaired.
Google Fonts, cdnjs, unpkg
Serve fonts and the 3Dmol.js and RDKit.js libraries to your browser. As with any CDN, your browser's request reveals your IP address to them.

Deleting your data

You can delete any saved item from your Workspace at any time. Deleting your account from the Workspace page permanently removes your account, every saved item and your fragment library; this cascades in the database and cannot be undone.

Security

Passwords are hashed with Werkzeug's PBKDF2 implementation. All traffic is served over HTTPS. That said, this is a research project run by one person, not a hardened commercial platform — do not store confidential or commercially sensitive structures here. If your work is proprietary, run the tools locally; the code is open.

The service is intended for university-level researchers, educators and students, and is not directed at children under 13.
